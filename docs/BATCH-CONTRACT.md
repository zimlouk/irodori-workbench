# Batch workbench API contract (2026-10-18)

Final implementation additions: Batch also contains deleted_segments:Segment[]. POST /api/v1/batches/{id}/restore-segment {revision,segment_id} restores an archived line and its unexpired audio. Overrides conflicts include choices:[{segment_id,text,overrides}] for explicit selection. Ordinary text updates don't reprocess unchanged source/rules. Output filenames add a stable segment suffix to avoid collisions when reordering duplicate lines. See BATCH-VALIDATION.md for final behavior and limitations.

Main agent implements backend; frontend worker must use this contract. Existing /api/v1/presets, assets, loras, status remain; reuse P2 ConfigEditor/OverridesEditor/preset/asset panels as useful. New default export BatchWorkbench, no props. Existing modules not to be modified by worker.

Types (JSON): Config = existing P2Config (seed string|null, same three parameters). Overrides = existing P2Overrides. Processing = {mode:'article'|'lines'|'passthrough',limit:number=120,short:number=20,merge_short:boolean=true,persistent_rules:string='',temporary_rules:string='',include_double:boolean=false}. Replacement rules one `old -> new` per line. Workbench defaults to lines; external API defaults passthrough.

Batch = {id,revision:number,source:string,origin:string ('workbench' or caller),created_at,updated_at,config:Config,processing:Processing,output_dir:string,segments:Segment[],conflicts:Conflict[],warnings:string[]}. Segment = {id,text,overrides:Overrides,input_revision:number,selected_job_id:string|null,selected_stale:boolean,effective_config:Config,attempts:Job[],output_path:string|null,output_error:string|null}. Jobs same existing job fields plus stale:boolean,expires_at:string|null,purged:boolean; audio_url null after purge. Conflict = {id,kind:'source'|'overrides',segment_ids:string[],before:string,after:string}. Deleted segments remain backend history and can be restored by recovering full old batch only if supported; no fake restore button.

GET /api/v1/batches?search= returns {items:Summary[]}, most recent first. Summary={id,origin,source,preview,updated_at,segment_count,completed_count,active_count}; no fixed total truncation. Batch view can also load old P2 projects via history migration handled backend; frontend doesn't show project concepts.
POST /api/v1/batches body {source?:string,config?:Config,processing?:Processing,output_dir?:string}; returns Batch 201. No required name. Creation performs processing, never inference. Empty source allowed.
GET /api/v1/batches/{id} -> Batch.
PUT /api/v1/batches/{id} body {revision,source?:string,script?:string,config?:Config,processing?:Processing,output_dir?:string,overrides?:{[segmentId]:Overrides}} -> Batch. source and script mutually exclusive; source reruns processing and three-way reconciliation; script is exact manually edited right text, nonempty lines are segments (max 4096 chars each, max500). config changes affect effective configs; unspecified fields preserved. revision conflict409 must retain local drafts, no blind retry. Blank drafts allowed. Backend maps stable IDs through edit/split/merge/move. Never frontend guess IDs by line index across asynchronous saves.
POST /api/v1/batches/{id}/resolve body {revision,conflict_id,choice:'keep'|'replace',segment_id?:string} -> Batch. source conflict replace uses after, keep retains manual text; overrides conflict uses explicitly chosen old segment_id settings, keep retains currently inherited config. Conflict UI must show before/after and explicit choice, never silently discard.
POST /api/v1/batches/{id}/generate body {revision,segment_ids?:string[],all?:boolean=false,reroll?:boolean=false} -> {items:Job[],batch_id:string}. Default generates only missing/stale/failed, skips active; reroll true requires exactly1segment and gives priority. May generate using visible right script despite unresolved conflicts (show notice). Must save draft before submit; creation/edit itself never generate.
POST /api/v1/batches/{id}/cancel body {} -> {cancelled:number}, only pending.
POST /api/v1/batches/{id}/segments/{sid}/select body {revision,job_id} -> Batch. Current-input succeeded, unpurged only; selected file republished; old versions show expiry.
POST /api/v1/batches/{id}/open-output body {} -> {opened:boolean}; local Windows folder open, click only, never automatically.
GET /api/v1/queue -> {items:Job[]}, active from all callers, each job has workbench_batch_id,origin,priority (1 high;0 normal), segment_id,text,status etc. highest priority first. UI cancel via owning batch ID. Every job frozen on submit.
GET /api/v1/preferences -> {revision,config:Config,processing:Processing,output_dir:string,last_batch_id:string|null}; PUT same object (revision required) -> saved object. Use for last defaults across new batch/reload; save after deliberate settings edits; restoring historic batch must not silently update defaults. No reset ephemeral replacement at new batch. Application API default settings independent from unsaved active editor.

Frontend behavior: two always side by side large textareas; source debounce500ms autosave/reprocess, right debounce autosave but no processing; serialize mutations, protect local unsaved content from polling responses. On click new/paste/restore/generate/settings/select flush pending edits. During async operations edits can continue; stale responses cannot overwrite new edits or switch target. Periodic GET merges audio state without replacing dirty texts/settings. Errors and409 preserve local content and offer reload/recovery. Keep per-batch drafts locally when switching and beforeunload if unpersisted.
Left buttons paste as new batch clipboard API; clear/new fallback; ordinary Ctrl+V edits same batch. Never infer new from paste. New batch inherits whole config/processing/output including temporary_rules, but no per-segment overrides. Recent drawer search and expandable compact batch rows with direct reroll (must not change editor), restore whole saved batch. Before restore save current draft. Follow API checkbox off default: polling history latest origin!='workbench', flush manual draft before switching; manual typing exits follow, follow only display not execution. Source shown. Queue persistent in footer while edit new batches. API callers same processing engine, no ST hardcoding.
Result compact rows show text,status,play,reroll,versions,settings. Click row locates textarea line via selectionStart/End/ref browser DOM normally in React allowed. Per-line settings use inherited toggles incl explicit caption'', refs[], lora null, seednull semantics. Version section all attempts incl stale, expiry, purified label; current audioonly shown by default. Select old valid version; stale can play but cannot select. New success automatically selects backend (if unchanged) and output republish.
Default voice select presets loads frozen config; deliberate save preset uses existing POST or versioned PUT, not auto-write. Asset upload/play/order. Emotion buttons insert at caret/selection. Output path editable, remember and open button. No automatic file dialog launch. Show fake mode clearly. Chinese UI, responsive, avoid project/revision internal jargon in normal flow.

Backend external routes /api/v1/synthesize (async returns Batch202), /v1/audio/speech (compatible sync/SSE) auto generate and priority; frontend only observes through batches/queue.

2026-10-18 parameter extension: config.parameters and per-segment overrides.parameters additionally accept CFG scales/mode/override/min-max-t, duration scale/fixed-min-max seconds, schedule/sway, truncation/rescale, KV options, reference normalization/peak protection, and trim_tail. See backend configuration.Parameters and frontend voice-parameters.ts for exact types. Absent or null optional parameters use runtime defaults; absent override inherits the batch, explicit null override selects runtime default. Compatible API inputs in irodori use the same config fields; older runtime_options are exposed through the editable config without duplicating parameter sources. Caption has one batch editor; preset caption is copied only on load and per-sentence caption wins.
